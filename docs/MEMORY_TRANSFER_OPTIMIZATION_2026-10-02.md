# 减少生涯数据跨线程复制（2026-10-02）

本轮在上一轮内存优化基础上，取消连续模拟的重复完整输入传输，并将保存时的校验、JSON 序列化和压缩合并到一次后台任务。相同五赛季场景的两次严格生产对照中，活动页面渲染进程平均 RSS 峰值从 798.48 MiB 降到 693.23 MiB，进一步下降约 13.2%。完整历史和存档格式保持不变，八次浏览器运行的最终存档校验值与比赛记录一致。本轮于 10 月 2 日开始，最终核验于 10 月 3 日完成。

## 实现方式

### 连续模拟复用后台最近一次结果

`simulationWorkerClient.ts` 用 WeakMap 登记返回状态所属的 Worker 和任务版本。只有输入正是该 Worker 最近返回的不可变状态对象，才发送 `REUSE` 操作和版本号；首次模拟仍发送完整输入。Worker 只保留最近一次成功结果，旧缓存不累积。

经理修改、读档、保存失败后重试旧状态、线程重启或并发版本失配，都会完整重同步。失败任务清空私有缓存；回退仍从主线程原始输入开始，不提前修改页面已提交的状态。返回的状态是不可变快照，后续经理修改必须替换根对象，现有 App 的命令和读档流程遵守这一约定。

生产浏览器实际消息显示：四次连续五场模拟，优化前四次均传完整状态，优化后为一次 `FULL` 和三次不带状态的 `REUSE`。结果仍完整返回主线程，以保留现有页面接口和“保存成功才更新页面”的提交顺序。

### 保存直接使用已经编码的内容

IndexedDB、localStorage 和符合原子迁移条件的默认适配器增加可选的 `getEncoded` / `setEncoded` 能力。保存 Worker 在一次任务内计算校验值、序列化和压缩，只返回校验值及编码内容。页面复用同一份内容写暂存和主档；旧备份在 Worker 内解码并校验，只回传头信息和原编码内容。

这取消了新存档完整 JSON 返回页面、再次送回 Worker 压缩，以及旧档完整 JSON 往返页面的过程。生产流程中的九次保存实际执行 `SERIALIZE_ENCODED_ENVELOPE` 和 `INSPECT_ENCODED_ENVELOPE`，没有使用旧的 `ENCODE_CHUNK` 保存链路；首次读档的解码和完整状态回传仍保留。

编码写入沿用原有槽位队列、暂存读回校验、备份恢复和 quota 处理。迁移仍使用原子插入，验证实际获胜内容后才删除旧副本。自定义、Memory 和云适配器没有编码能力时继续使用原路径；不改变存档 schema 或 gzip 格式，也不将资源不足当成坏档。

## 同场景生产测量

固定存档：1,225 名球员、5 个归档赛季，未压缩 JSON 5,171,193 bytes。每次新建隔离 Chromium，依次进行 130 次导航、20 场比赛和 5 次手动保存。以下四次都使用同一份带消息监测的脚本；操作顺序相同，顺序执行。对照构建从最终源码的隔离副本生成，仅回退七个既有内存相关生产文件，逐文件核对确认其他生产源码一致；新增协议文件在对照版本未被引用。这样排除同时进行的交易性能改动。单位为 MiB。

| 阶段 | 优化前对照 1 | 优化前对照 2 | 优化后 1 | 优化后 2 |
|---|---:|---:|---:|---:|
| 全流程活动页面 RSS 采样峰值 | 786.96 | 810.00 | 702.26 | 684.19 |
| 模拟与自动保存阶段峰值 | 774.46 | 762.81 | 529.10 | 631.83 |
| 手动保存阶段峰值 | 786.96 | 810.00 | 595.19 | 672.85 |
| 操作后静置 5 秒 | 531.41 | 532.04 | 413.04 | 510.63 |
| 随后静置 30 秒 | 436.18 | 436.51 | 344.16 | 441.98 |
| 最后主线程 GC 后 JS 堆 | 19.62 | 19.62 | 19.61 | 19.63 |

早先冻结构建的两次未启用消息监测运行，峰值为 801.57 / 810.07 MiB；同构建启用监测后为 832.06 / 800.72 MiB。这四次原始结果一并保留，但旧冻结构建还含其他并行源码差异，先前据此计算的约 15.1% 不作为本轮独立收益。最终 13.2% 只使用上表仅回退内存代码的严格对照。

所有八次运行最终 `stateHash` 为 `6f1aa29d8e9da47a`、revision 为 10、日历为 42、战绩为 15 胜 5 负；包含总得分、主客场和各对手记录的完整球队记录逐字段一致，页面错误列表均为空。

后台保留状态确实有常驻成本：静置后模拟 Worker 的存活 JS 堆从约 2.84 MiB 增加到 7.40 MiB，多约 4.56 MiB；存档 Worker 都回收到约 0.44 MiB。页面总 RSS 仍受浏览器分配器、缓存和系统内存压力影响，优化后两次静置值差异明显，其中一次略高于对照，不能承诺常驻占用稳定降低 13.2%。

## 改动和验证

生产源码：`src/app/simulationWorkerClient.ts`、`simulation.worker.ts`、新增 `simulationWorkerProtocol.ts`；`src/storage/SaveService.ts`、`SaveCodec.ts`、`SaveCodec.worker.ts`、`SaveEnvelopeCodec.ts`；`src/platform/storage/StorageAdapter.ts`。对应六个测试文件覆盖线程边界和编码保存路径，没有新增依赖。

模拟边界、协议与既有任务的 29 项定向测试通过。包含真实 structuredClone 边界、固定 Seed 完整结果对照、并发失配、线程错误/重启、未提交结果失效，以及保存失败后用此前已提交的 Worker 返回对象重试。存档测试覆盖编码内容复用、暂存读回异常不提交、旧格式/坏档/资源失败、迁移竞争和 quota 回收。

最终全量 117 个文件、1016 项测试通过，TypeScript、生产构建和静态差异检查通过。最终构建与实测版本的 JS 校验值完全相同。技能提供的浏览器客户端经隔离存档和按钮定位适配后，完成一次五场模拟、自动保存与两轮截图/状态检查；结果为日历 10、5 胜 0 负、动画结束，没有浏览器错误，截图已人工检查。独立只读审查未发现阻塞问题；建议的不可变约定注释和保存失败重试回归已补齐。

所有测量浏览器和本轮三个临时 HTTP 服务已关闭。

## 口径、复现与边界

macOS / Chromium 151.0.7922.34，393×852、DPR 3，生产 inline Worker。每 250 ms 采样，阶段快照只强制主线程 GC，不在操作中强制 Worker GC。页面 RSS 取活动 renderer，排除备用 renderer；GPU 另计，进程树 RSS 不作为游戏独占内存。采样可能漏掉短于 250 ms 的峰值。

本轮已减少冗余复制，仍保留模拟结果的完整回传和每次保存向存档 Worker 发送一次完整状态。更彻底的方案需要让后台统一持有生涯数据并接收经理命令，页面只接收视图和增量，同时设计保存失败的提交/回滚边界。长生涯历史按需加载也需单独设计与迁移验证。
