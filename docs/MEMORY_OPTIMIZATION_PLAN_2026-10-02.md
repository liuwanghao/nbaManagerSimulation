# 内存优化执行计划（2026-10-02）

目标：降低模拟/保存期间的页面 RSS 峰值，使用相同生产构建测试方法和固定 5 赛季存档对比。先处理已有证据支持的重复分配，不承诺未经复测的降幅。

1. 先运行现有存档恢复、压缩、随机数和后台模拟测试，新增旧存档哈希兼容与备份一致性回归。
2. 保存校验改为逐段计算，保持 `stableHash(stableSerialize(state))` 的现有双层字符串编码、FNV-1a 64 和 UTF-8 完全一致。比赛 Seed 和随机数算法不改。
3. 保存旧版本时，后台只返回校验后的存档头和原序列化内容；避免将旧完整状态送回主线程、再发送到后台重序列化备份。复用现有损坏/暂存恢复规则。
4. 健康主存档不做无意义的整份重新序列化；必要的槽位修正、旧缺失 saveId、暂存/备份恢复仍持久化。
5. 用同一套新生涯/5 赛季模拟、保存场景测量 before/after，验证实际比赛结果、存档 hash 和恢复逻辑；无收益的改动不保留。
6. 运行全量测试、TypeScript、生产构建和 diff 静态检查，记录收益与剩余限制。

复测后的补充（先验证再保留）：连续模拟日历目前每天调用默认不可变 `simulateLeagueDay`，在 Worker 已持有独立状态的情况下仍反复复制当前赛季。增加明确的 Worker 私有状态执行选项，复用现有 `mutate` 通道；主线程回退保留原来的不可变行为。先覆盖单场、五场、指定日期、交易截止事件和原输入保持不变等回归，逐字段核对结果、帧与进度，再对同一五赛季存档做生产复测。

本轮不改存档 schema，不删除历史或退役球员，不引入依赖，不部署或覆盖发布 ZIP。历史分层持久化涉及多页面与旧存档迁移，留待单独评估。

写入责任：哈希 helper 与测试是独立子任务；SaveService 保存/恢复流程与测试是独立子任务；主代理负责 codec Worker 接口、集成和浏览器实测。保留工作区已有改动。

补充写入责任：日历模拟子任务仅负责 `simulationTask.ts`、`simulationTask.test.ts` 与 `simulation.worker.ts`；其余文件仍由原责任人处理。

执行完成：原构建、仅存档优化、最终组合优化各完成两次相同五赛季场景；补充一组新生涯对照。最终五赛季峰值 1034–1056→786–789 MiB，平均下降 24.68%；新生涯 480.48→394.58 MiB，下降 17.88%。所有场景实际存档校验值与比赛记录一致。最终 114 文件/959 项测试、TypeScript、生产构建、diff 检查与独立审查通过。收益和真机/长生涯限制记录在 `MEMORY_OPTIMIZATION_2026-10-02.md`。
