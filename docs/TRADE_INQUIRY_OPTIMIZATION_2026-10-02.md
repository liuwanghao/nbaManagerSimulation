# 组合询价性能优化

请求：降低 6 名球员组合询价在桌面约 14 秒的耗时，减少较慢手机的卡顿。

## 修改前计划

1. 在固定 Seed、阶段和资产组合上记录旧实现的完整报价、询价计数及拒绝结果，先建立回归基线；用 CPU profile 确认热点。
2. 将不随选秀权组合变化的球员校验、工资匹配、阵容适配与核心球员溢价移到球员组合层；选秀权资产和连续首轮规则继续独立校验。
3. 复用本次询价的计算结果，缓存仅在一次不可变询价内有效；保留候选组合、遍历顺序、浮点运算顺序、Seed、报价排名及刷新惩罚。
4. 对比相同场景耗时和完整结果；验证薪资、伤病、人数、首轮限制、成交与刷新，再跑全量测试、类型检查、构建、第二赛季 Headless 和浏览器交易回归。

不新增依赖，不改变交易价值或规则，不限制玩家资产选择，不覆盖玩家存档，不发布线上。

## 已实施的简化

- `src/game/trade/TradeService.ts` 提取旧球员归属、人数/可用人数/薪资、连续首轮校验；公开成交校验继续以旧顺序完整执行。
- 选秀权组合在每个对手球队上预检一次；球员组合的规则、溢价和双边适配计算一次，取消两层循环中的重复工作。
- 一次询价内复用球员估值、签位估值、原球队选秀强度和签位 ledger。下一次命令重建缓存。
- 固定评分中的随机偏好最大为 3，只有 `baseScore + 3 < best.score` 才跳过无法胜出的候选的哈希和报价分配；同分、Seed、排序和候选范围保持原规则。

基准脚本：`tools/headless/benchmark-trade.ts`、`tools/qa/trade-inquiry-performance.mjs`。原始浏览器数据与截图在 `reports/qa/2026-10-02/trade-inquiry-performance/`，Node CPU profile 在本次临时目录中。
