# 交易黑屏排查与修复 — 2026-10-02

本轮修复已复现的交易详情渲染崩溃，并继续审计交易列表、自定义交易、成交后清理和应用入口。所有浏览器验证使用全新隔离上下文；未读取或覆盖玩家原存档。工作区其他并行任务的改动保留。

## 已确认的触发路径

1. 本队 5 人可用，报价送出 1 名可用球员、得到不可用球员。原校验只检查名单总数，仍认为报价合法；点开详情后构建交易后轮换抛出 `ROTATION_REQUIRES_FIVE_AVAILABLE_PLAYERS`。没有错误边界时 React 清空页面。
2. 交易前只有 4 人可用，但交易能补足到 5 人。交易本身能成交，原预览仍因构建交易前轮换抛错。同样的问题也影响不改变阵容的合法纯选秀权交换。
3. 异常报价引用不存在的球队时，校验已返回失效，但列表仍读取该球队的 `fullName` 而崩溃。
4. 异常报价缺失资产数组时，校验前的 `map` / `reduce` 会崩溃。最早引入 TradeOffer 的版本已有四个必填资产数组，目前没有证据这是正常旧存档迁移造成的问题。

第 1、2 项使用正常数据字段的受控阵容状态复现；第 3、4 项属于异常数据防御缺口。尚无玩家原档或错误日志，不能断言所有玩家反馈都由这些路径引起。

修复后继续检查刷新、球员资料、筛选浮层、成交失败和计算耗时。本轮未修改业务代码，没有再复现整页被清空的交易黑屏，但确认了两个尚未修复的卡住风险：
